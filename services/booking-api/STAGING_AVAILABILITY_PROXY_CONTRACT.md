# Hosted staging availability: read-only proxy contract

**Status: design only — no endpoint deployed or enabled.** The existing local bridge at `127.0.0.1:4328` remains the only working booking-master source.

## Browser contract
When `PUBLIC_BOOKING_STAGING_READ_ONLY_ENABLED=true` is explicitly set in a **private staging build**, the browser fetches `GET /api/staging/availability` on the same origin with `cache: no-store`. The endpoint must return the existing `LIVE_STAGING_MASTER_READ_ONLY` schema generated by `master-occupied.mjs`, including `capturedAt`, `firstNight`, `lastNight`, `lastCheckout`, and occupied date ranges for Geranium and Honeysuckle. It must not include guest identifiers, contact details, booking IDs, AWS tokens, or raw DynamoDB rows.

## Server-side requirements
- Restrict access to authenticated, authorised staging reviewers **at the edge or server**; a hidden URL and `noindex` are not access controls.
- Route same-origin `/api/staging/availability` to a dedicated GET-only handler. Never expose the local development server or embed AWS credentials in browser code.
- Use a least-privilege role with DynamoDB `Query` on the **specific staging booking-master table** only. Use strongly consistent, paginated reads and the existing expiry rules in `master-occupied.mjs`.
- Return `Cache-Control: no-store`, `Content-Type: application/json`, `X-Content-Type-Options: nosniff`. Deny other methods and paths. Fail closed with 503 on DynamoDB failure.
- Require the exact schema and a fresh `capturedAt` (client rejects snapshots older than two minutes). Apply throttling, logging without PII, and avoid broad CORS.
- Ensure CloudFront behaviour and authentication protect both the HTML preview and API. Review deployment/IAM changes before execution.

## Verification before enabling
1. Confirm staging reviewers cannot access the preview or API without authentication.
2. Compare occupied ranges against the existing staging booking master, including the 28 Aug–4 Sep 2027 both-cottage reservation.
3. Confirm failures, expired snapshots and malformed data show unavailable dates and block quote progression.
4. Confirm EN/FR/NL booking previews remain `noindex`, reservation submission stays disabled, and no SumUp/SES/booking writes occur.
5. Obtain explicit approval before enabling the hosted read-only flag or deploying any infrastructure.

**Production:** unchanged. **Booking acceptance:** disabled.
